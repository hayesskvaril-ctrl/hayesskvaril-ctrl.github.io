# Keeping the site current: how updates work

This is the system for spotting regulatory changes, checking them, and updating the site in one go.

## In plain English (for the site owner)

1. **Something changes.** You'll hear about it one of three ways:
   - **The weekly regulator watch.** Every Monday morning a free automatic check reads the latest announcements from APRA, ASIC, Treasury and the Attorney-General's Department. If there is anything new, GitHub emails you an issue called "Regulator watch …" that lists each announcement and the pages it may affect. AUSTRAC, the OAIC, the ACCC and the ASD can't be read automatically, so they are checked by hand.
   - **You spot it.** Use the **Report a regulatory change** form (on the Key facts register page, or GitHub → Issues → New issue). It takes a minute and works on a phone.
   - **A reader spots it.** Every page has a **Suggest a correction** link.
2. **Ask Claude to process it.** Say "process the regulator watch issue" or "process the open issues". Claude checks each item against the official source, updates the site, and closes the issue with a note of what changed.
3. **One fact, updated once.** Key dates, amounts and limits are kept in one register. Changing a fact there changes it on every page that shows it, and Claude is shown every other place that still mentions the old value.
4. **Everything is recorded.** Each fact shows on the public [Key facts register](https://hayesskvaril-ctrl.github.io/about/fact-register.html) with its source and when and how it was last checked. Changes also appear on What's new, and errors get a visible correction note.

## The parts

| Part | Where | What it does |
|---|---|---|
| Key facts register | `_scripts/facts/facts.json` | One record per fact: value, status, official source, when and how it was checked, history of changes |
| Fact markers on pages | `<span class="fact" data-fact="ID">value</span>` | `build_facts.py` (run by `sync_layout.py`) keeps every marked copy identical to the register |
| Update tool | `_scripts/update_fact.py` | `set`, `confirm`, `add`, `show`, `list --due` |
| Linking tool | `python3 _scripts/build_facts.py --wrap` | Links plain mentions of a fact on article pages (only where the sentence or the page title matches the fact's context words, never in news, transcripts, review dates or correction notes) |
| Public register page | `/about/fact-register.html` | Generated by `build_facts.py` |
| Weekly regulator watch | `.github/workflows/regulator-watch.yml`, `_scripts/watch/` | New announcements with suggested pages; looks for every fact on its official source page |
| Watch results | `watch-data` branch (not published) | `pull_watch.py` copies them here; `run_checks.py` does this automatically |
| Report forms | `.github/ISSUE_TEMPLATE/` | "Report a regulatory change" and "Suggest a correction" |
| Checks | `python3 _scripts/run_checks.py`, section 8 | Facts due for a re-check, facts the watch couldn't find on their source, new announcements to process |

## How each fact is checked

`checked.how` in the register is one of:

- **official**: read on the regulator's, Treasury's or legislation website by a person.
- **auto**: found on its official source page by the weekly watch (shown automatically from `auto_checks.json`).
- **expert**: confirmed by the site's expert reviewer.
- **secondary**: confirmed only through reliable secondary sources (law firm summaries, trade press, search results). This is the weakest level: the weekly watch, or a person, should confirm it on the official source.

Re-check timetable (unless a fact has its own `recheck` date): proposals and consultations 30 days, estimates 60, finalised but not yet started 90, in force and reports 365.

## Procedure for Claude: processing an update

1. **Read the trigger.** List open issues labelled `regulator-watch`, `regulatory-change` and `correction`. Run `python3 _scripts/pull_watch.py` and read `_scripts/watch/latest_report.md`.
2. **Verify on the official source.** Official sites may be blocked from Claude's sandbox. If so, use the weekly watch result (the watch can read them), and WebSearch for the official release. Record honestly how it was checked (`--how official` only if the official text itself was read, by you or by the watch; otherwise `secondary`). Never invent a value.
3. **Update facts first.** For a changed date or number: `python3 _scripts/update_fact.py set ID "new value" --how … --note "…"` (add `--status` if it moved from proposed to finalised, for example). For a re-check with no change: `update_fact.py confirm ID --how … --note "…"`. For something new worth tracking: `update_fact.py add …`, then `build_facts.py --wrap`.
4. **Rewrite the words around it.** `set` lists every other mention of the old value (unlinked page text, dated news, and data files such as `tracker_data.py`, `grc-builder-data.js`, `playbooks_data.py`, `briefings_data.py`). Fix them, and fix wording that the change makes wrong (for example "proposed" → "final"). Dated news articles are a record of the time: add an update note rather than rewriting them.
5. **Tracker and records.** Update `_scripts/tracker_data.py` (and `AS_AT`), add a line to `changelog_data.py`, and add a visible correction note (class `no-fact`) on the page if the site had been wrong.
6. **Rebuild and check.** Rebuild any generators whose data changed, then `sync_layout.py`, `check_links.py`, `run_checks.py`. Commit, publish, and close each issue with a short comment saying what changed and on which pages (end the comment with the Claude Code footer).
7. **Flag for expert review** anything in the owner's specialist areas (see CLAUDE.md §2).

## What the weekly watch can and can't read

| Source | How it is read |
|---|---|
| APRA | News and publications page |
| ASIC | Its sitemap (ASIC's newsroom pages are built in the browser, so the sitemap is used to list media releases) |
| Treasury | Consultations page and the Treasurer's and Financial Services Minister's media releases |
| Attorney-General's Department | Consultation hub |
| AUSTRAC, ACCC, ASD (cyber.gov.au), OAIC | **Not readable automatically**: AUSTRAC, the ACCC and the ASD block automated reading from cloud servers; the OAIC builds its news list in the browser and its feed and sitemap are out of date. The report lists them under "Check by hand", and the monthly upkeep includes checking their news pages. |

Facts whose official page can't be read automatically carry `"autocheck": false` with a note, and are re-checked by hand on the normal timetable.

## When the watch needs attention

- **A source finds nothing** (listed under "Sources where nothing was found"): the regulator has probably redesigned its news page. Update its `pages` or `pattern` in `_scripts/watch/sources.json`.
- **A fact is "not found" on its source** every week although it is right: the page words it differently or the fact has moved to another page. Point `source.url` at the page that states it, or use the value's exact wording.
- **Run it now**: GitHub → Actions → Weekly regulator watch → Run workflow (or ask Claude to run it).
